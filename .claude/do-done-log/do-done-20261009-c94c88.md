What I tested:
- **Parity:** the helper sees the same windows, in the same order, as Hammerspoon's own window list, and the new save matches the old code's last one entry for entry.
- **Shared saves:** two saves requested at once use one helper run.
- **Sleep save:** deliberately still reads in Hammerspoon, so it finishes before the Mac sleeps.
- **Unresponsive app:** I paused Calendar with `SIGSTOP`; its window was kept.
- **Broken helper:** with the helper made unrunnable, saves fall back to the old way instead of stopping.

**A bigger find along the way:** every Hammerspoon reload froze for 8.7 s while loading `data/screen-memory.json` (811 KB). Who's to blame:
- **Hammerspoon's JSON decoder** is where the time goes. It slows with the square of the number of same-sized objects: 400 of them took 311 ms, while the same data as plain strings took 4.7 ms.
- **screenmemory** sets it off. It stored one small object per window and screen, and kept every title it ever saw for 30 days.
- **The do-done tab** fed it. The clock in its title added a new Chrome title every minute, 1,401 in all.
- **Not the disk or Dropbox:** reading the file took 1 ms.

The file is now stored flat and keeps the 200 newest titles per app. Only Chrome and kitty lost titles; Bear's 78 are untouched, and all surviving entries match the old file exactly. It's down to 118 KB and loads in under a second.
