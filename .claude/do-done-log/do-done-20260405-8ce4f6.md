# Multi-Display Config Support

**Scope:** `lua/layout.lua` only — all other modules already display-count-agnostic

## Context

The layout system hardcodes `TARGET_DISPLAY_COUNT = 5` and uses single layout files (`window-layout.json`, `window-layout-manual.json`). Auto-save, auto-restore, wake drift detection, and periodic backups only work for the 4×LG 32" setup. You now alternate between three configs:

| Config | Screens | Position map |
|--------|---------|-------------|
| **quad-32** | 5 (built-in + 4× LG 32") | bottom, center, top, left, right |
| **samsung-portrait** | 3 (built-in + 37" Samsung portrait + 43" TV) | bottom, center/top, left |
| **native** | 1 (MacBook built-in) | bottom |

Screen count alone differentiates them (5, 3, 1).

## Design

### 1. Config registry (replaces `TARGET_DISPLAY_COUNT = 5`)

```lua
local KNOWN_CONFIGS = {
  [5] = { name = "quad-32",          lunarSync = true  },
  [3] = { name = "samsung-portrait", lunarSync = false },
  [1] = { name = "native",           lunarSync = false },
}
```

New module state: `activeConfig` (entry or nil) and `activeCount`. Counts 2 and 4 are "transitional" — logged and ignored.

### 2. Per-config layout files

- `data/window-layout-5.json`, `window-layout-3.json`, `window-layout-1.json`
- `data/window-layout-manual-5.json`, etc.
- `data/layout-backups/layout-1m-03-c5.json`, etc.

Path functions: `dataFileForCount(n)`, `manualFileForCount(n)`, `backupNameForCount(ring, slot, n)`, plus `currentDataFile()` / `currentManualFile()`.

Ring indices become per-config tables.

### 3. Stability window (ramp-up protection)

Problem: plugging a USB-C dock makes screens appear over 5–10s. Count passes through 2→3→4→5. Count=3 during ramp-up would falsely trigger samsung-portrait restore.

Solution: after the existing 2s debounce, add a 3s stability recheck. If count changed, abort. Total settling: 5s.

```
screen change → [2s debounce] → known config? → [3s stability] → count still same? �� transition
```

### 4. Transition logic (`transitionToConfig()`)

When stability confirms a new known config:

1. **Do NOT save the old config** — by this point macOS has already shuffled windows from disconnected screens. Saving would overwrite the good layout with garbage. We rely on periodic save (60s) + `triggerSave()` (after user moves) to keep each config's file fresh.
2. Stop periodic save, cancel retry, clear protection.
3. Switch `activeConfig` / `activeCount` to new config.
4. After 1s settle, restore from new config's layout file (with protection + retry).
5. Start periodic saves for new config.
6. Lunar sync only if `newCfg.lunarSync`.

First-time (no layout file): skip restore, start periodic saves. File created on first save cycle.

### 5. Transition matrix

| From → To | Save old? | Restore new? | Lunar? |
|-----------|-----------|-------------|--------|
| quad-32 → samsung-portrait | No (shuffled) | Yes | No |
| quad-32 → native | No (shuffled) | Yes | No |
| samsung-portrait → native | No (shuffled) | Yes | No |
| native → samsung-portrait | No | Yes | No |
| native → quad-32 | No | Yes | Yes |
| samsung-portrait → quad-32 | No | Yes | Yes |
| any → transitional (2, 4) | — | — | — |

### 6. Function-by-function changes

| Function | Line(s) | Change |
|----------|---------|--------|
| *(constants)* | 17–22 | Remove `dataFile`, `manualFile`, `TARGET_DISPLAY_COUNT`. Add config table, path functions, active state |
| *(ring indices)* | 42–43 | Scalar → table |
| `rotateRing1m/10m()` | 245, 254 | Per-config path + index |
| `M.save()` | 380 | Guard `activeConfig`, write to `currentDataFile()` |
| `M.restore()` | 473 | Read from `currentDataFile()` |
| `M.manualSave()` | 488 | Copy to `currentManualFile()` |
| `M.manualRestore()` | 504 | Read from `currentManualFile()` / fallback |
| `M.autoSave()` | 856 | Guard: `not activeConfig or count ~= activeCount` |
| `startPeriodicSave()` | 913 | Guard with `activeCount` |
| `onScreenChange()` | 939 | **Rewrite**: debounce → stability → `transitionToConfig()` |
| `M.onWake()` | 993 | Use `activeConfig`/`activeCount` |
| `M.init()` | 1061 | Migration, detect initial config |

New functions: `configForCount()`, path builders, `currentDataFile/ManualFile()`, `migrateOldFiles()`, `transitionToConfig()`.

No changes to screenswitch.lua, screenmemory.lua, stepper.lua, or focus.lua.

### 7. Migration

On first `M.init()`, if `window-layout-5.json` doesn't exist but `window-layout.json` does: copy old files to count-suffixed names, copy backup rings. Leave old files as safety net.

### 8. gather() — no change

Not auto-called on disconnect. Stays as manual escape hatch.

### 9. Edge cases

| Edge case | Handling |
|-----------|---------|
| Ramp-up 1→2→3→4→5 | 3s stability recheck catches it. Worst case (very slow dock): brief samsung restore then quad-32 — self-healing. |
| Transitional count (2, 4) | Ignored. autoSave guard skips. |
| No layout file for new config | Skip restore, first periodic save creates it. |
| Periodic save during transition | autoSave guard: count ≠ activeCount → skip. |
| Screen flicker during stability | Next event cancels stability timer, restarts debounce. |
| Wake at any config | onWake reads currentDataFile(), checks drift against activeCount. |

### Verification

5. Manual save/restore writes to correct per-config file
6. Ramp-up: console shows `screens-stability-failed` if count changes
