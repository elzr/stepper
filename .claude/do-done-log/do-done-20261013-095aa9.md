Right ⌥P belongs to rcmd again, and only left ⌥P paginates in Bear. One correction: the live-slot work (◆P) didn't cause this. It was fleet's **F043/L004 auto-pagination**, made yesterday.

**Why it broke:** auto-pagination bound ⌥P as an ordinary Hammerspoon hotkey whenever Bear was in front. That kind of hotkey can't tell left ⌥ from right ⌥, and it gets the key before rcmd does. So in Bear, right ⌥P paginated instead of bringing Photos forward. The code comment even said "as BTT's ⌥R resizes images", so the model was in mind. But BTT's ⌥R only answers the left ⌥, and that part never made it into the code. Nobody checked right ⌥P before calling it done, and that's on us.

**The fix** (in `auto-pagination.lua`):
- ⌥P is no longer a hotkey. It now watches keystrokes directly, only while Bear is in front, and checks which ⌥ is down. Left ⌥P paginates. Right ⌥P passes through untouched to rcmd.
- ◆` still paginates as before.
- Holding the key down doesn't paginate again or type π.

**Checked:**
- With fake keystrokes, only left ⌥P paginates. Right ⌥P, both ⌥s together, left ⌥⇧P, left ⌥O and plain P all pass through.
