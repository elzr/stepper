## Claude:
I found the cause, and it's BTT rather than L008. L008 only ever adds a width comment and never pastes anything; since your image wasn't resized, L008 didn't act on it at all.

**What happens:** BTT's "Paste text" puts `# ☀️⸻⸺` on the clipboard, sends ⌘V, then puts your old clipboard (the image) back. BTT's own log shows it restoring only **50–80 ms after the ⌘V**, every time this week:

```
14:19:53.220  paste 1   ← zday text on clipboard, ⌘V sent (L008 logged that ⌘V at .249)
14:19:53.327  paste 3/4 ← old clipboard (your image) put back
```

If Bear hasn't read the clipboard by then, it pastes whatever is back on it, which was your image. Bear is usually fast enough, but at 14:19:53 and 14:19:59 it wasn't. BTT's timing is the same as on 10-07, so this isn't a regression from its 10-02 update. It's a tight race that Bear lost today.

**Who's to blame:**
- **Loses it:** BTT, whose restore delay is too short.
- **Sets the stage:** Bear, which sometimes takes longer than ~60 ms to handle ⌘V.
- **Our share, and it's small:** the ⌘V passes through Hammerspoon's keyboard watchers, which delayed it 8–29 ms before Bear got it.
- **Cleared:** L008's note reads. I suspected that L008 reading the whole note on every keystroke kept Bear busy. I added a timer to `lua/bear-paste.lua` (only how long each read takes, not what it says) and it shows **0.3 ms** per read on a 12.9 KB note.

**Proposed fix:** BTT has a hidden setting, `BTTPasteClipboardRestoreDelay`. It's currently unset, and I didn't find its default; the logs show 50–80 ms in practice. Setting it to 0.3 s should give Bear plenty of time, and your image still comes back:

```
defaults write com.hegenberg.BetterTouchTool BTTPasteClipboardRestoreDelay -float 0.3
```

I haven't run this, because I propose changes to other apps' settings rather than writing them myself. Say the word and I'll run it, then check BTT's log on your next zday to confirm it now waits longer. I'm assuming the value is in seconds, like BTT's other delay settings.

**One open question:** an image pasted right after a ⌘V that L008 caught should have been shrunk. L008 logged nothing for either paste, which may be a separate L008 bug. Once BTT stops pasting the image this one can't happen anyway, so I'm leaving it unless you want me to dig.

I haven't committed the timing change yet; I'll commit it together with the fix.
