<!--DO_DONE_BREAK_V1-->

I found it. Your Caps Lock tap is triggering **Raycast's "Sleep Displays" command**. The displays never actually toggle: they go to sleep, and the next key or mouse movement wakes them.

**How it happens:**
1. Hyperkey is set to send **Escape** when Caps Lock is tapped alone ("quick press" setting, `quickHyperKeycode = 53`). It sends that Escape with the hyper modifiers still held, so Raycast sees **⌃⌥⇧⌘⎋**.
2. Raycast's **System › Sleep Displays** is bound to exactly that key, ◆⎋. Fleet F002's keybinding census first saw that binding at **2026-10-14 23:21:39**, last night. No Claude session set it, so it was set in Raycast's own settings.
3. Raycast runs `pmset displaysleepnow`, which puts all displays to sleep.

**How I confirmed it:** I caught your tap in the act. At 07:40:41 the system's power log shows process 78326 asking for display sleep, and my watcher shows that process was a `pmset` started directly by Raycast. Plaud also starts `pmset` every few seconds, but none of its runs ever asked for sleep, so it's not involved. The same pattern explains this morning's run of nine sleeps between 07:35 and 07:38.

**The fix is in Raycast's settings**, which I can't change because its hotkeys live in an encrypted database. Go to Raycast Settings → Extensions → search "Sleep Displays" → clear or change its hotkey. Any combination other than ◆⎋ stops it. If you want to keep a hyper shortcut for sleeping the displays, pick a free ◆ key in the F002 keymap. If the binding was an accident, just delete it.

The other side of the clash is Hyperkey's tap-Caps-for-Escape. You probably want to keep that, so I'd leave Hyperkey alone. Once you've changed the Raycast hotkey, I can re-run the census so the keymap drops ◆⎋.
