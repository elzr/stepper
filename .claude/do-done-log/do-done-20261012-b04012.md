## Claude:
**Cause found: AltTab's shortcut 1 is set to "Hold" on release, not "Focus".** Nothing in Stepper is swallowing anything. Every quick ⌘⇥ you made this afternoon reaches AltTab fine, and its log shows it seeing the ⌘ release within a few dozen milliseconds. It then does nothing, because the per-shortcut override for shortcut 1 reads "do nothing on release, focus with ↩". The hold-release action has never fired once in either of its logs.

**How it got there (yes, something we did, via an AltTab bug).** On 2026-10-09 around 15:10 you consolidated AltTab's three shortcut slots into one, moving ⌘⇥ from slot 3 to slot 1 (recorded in F002). AltTab's slot-removal code copies each lower slot's settings down with `UserDefaults.object(forKey:)`, which also returns registered defaults, so it wrote all five per-shortcut "override" keys into your preferences with their default values. Four of them equal the global defaults and are harmless. The fifth, the release style, defaults to Hold while the global is Focus, so shortcut 1 silently switched to Hold. The code is unchanged in 11.9.1 and on master. It is not a trial downgrade: your Pro license is active (key in the Keychain, validated 2026-10-09).

**What I did.** Read-only diagnosis, plus one thing: I quit and relaunched AltTab once (a few seconds of native ⌘⇥). I tried to apply the fix, but the auto-mode classifier refused both deleting the key and writing it, so your preferences are untouched.

**The fix, your call, either way takes a minute:**

- In AltTab: menu bar icon → Settings → Controls → Shortcut 1 → "After keys are released" → **Focus**. No relaunch needed.
- Or from here, with AltTab quit first:

```
! osascript -e 'tell application "AltTab" to quit'
! defaults write com.lwouis.alt-tab-macos shortcutStyleOverride -string "0"
! open -g -a /Applications/AltTab.app --stdout ~/Library/Logs/AltTab/alttab.log --stderr ~/Library/Logs/AltTab/alttab.log --args --logs=debug
```
