The reframe is the whole answer: **what we're calling "flakiness" isn't randomness — it's two specific, named, mechanical deaths** (stale observer bound to a dead PID; disabled eventtap). Once a flaky symptom resolves to a *known mechanism*, it stops being "flaky" and becomes an ordinary bug you can engineer against.

**Nowhere on disk.** `hs-console.sh` calls `hs.console.getConsole()` — that's Hammerspoon's **in-memory console buffer**. It's ephemeral:
- It's **wiped on every reload/restart** (so each `hs-reload.sh` I ran this session erased the prior buffer), and
- it's **size-capped** — old lines scroll off as new ones arrive.

Every `logger.i(...)` in `bear-paste.lua` goes only there. So all those "traces" were volatile — read live, gone soon after.

## 2. What NDJSON is

**Newline-Delimited JSON** — one complete JSON object per line, not a big `[...]` array:
```
{"t":0,"i":0,"note":"session start @ 20260420-093908"}
{"t":3.923,"note":"MARK RUN_BEGIN"}
```
It's the standard log format because you can **append** one line at a time, **stream/grep** it, and a crash mid-write only costs the last line (a JSON array would need rewriting the whole file every time).
