## Why "long stretches, then fine again" is the key symptom

## The subtlety that makes naive no-op logging insufficient

If failure mode #1 or #2 is the cause, **the observer callback never runs at all** — so a `logger.i("rejected: ...")` inside `onObserverFire` would log *nothing*, same as today. The absence of a log can't distinguish "observer is dead" from "observer fired and rejected."

- **No-op logging** at each gate inside `onObserverFire` (catches the logic/timing rejections — rows 2–5).

## How you fix flakiness

> The current design is **edge-triggered**: it reacts to the `launched` event *once* and then assumes the binding stays good forever. The fix is a **level-triggered reconciler**: periodically compare *actual* state to *desired* state and correct any drift.

## 2. What NDJSON is

**Newline-Delimited JSON** — one complete JSON object per line, not a big `[...]` array:
```
{"t":0,"i":0,"note":"session start @ 20260420-093908"}
{"t":3.923,"note":"MARK RUN_BEGIN"}
```
It's the standard log format because you can **append** one line at a time, **stream/grep** it, and a crash mid-write only costs the last line (a JSON array would need rewriting the whole file every time).
